# Running the reasoner

How to check the ontology with HermiT in Protégé, what it already caught, and why a "consistent" verdict on its own proves nothing.

---

## Which file to open

Open **`ontology/paleont_merged.owl`**.

Protégé opens one ontology at a time. The clean way would be an `owl:imports` from the A-Box to the T-Box, but the project IRI `https://w3id.org/paleont/` does not resolve on the web yet (it is a placeholder to be registered later), so Protégé would fail to fetch it and ask you to map the import to a local file by hand.

For a consistency check that is not worth the trouble. The merged file is regenerated by `tools/build.py` along with everything else, and it is an artefact of verification, never a working file. Do not edit it.

---

## Steps

1. **File, Open**, then `ontology/paleont_merged.owl`
2. **Reasoner, HermiT** (tick it in the menu)
3. **Reasoner, Start reasoner**
4. Watch the status bar. A red popup means the ontology is inconsistent.
5. With a consistent ontology, classes shown in **red** in the hierarchy are unsatisfiable: no individual can ever belong to them. That is a modelling error even without an inconsistency.
6. To see **why** something was inferred, click the **`?`** beside an inferred axiom, or open **Window, Views, Ontology views, Explanation**.

Two views repay attention after the reasoner starts:

- **Entities, Individuals**: each individual now shows its **inferred** types in yellow alongside the asserted ones. That is the reasoner's work made visible.
- **Classes**: inferred parents appear in yellow.

## Two problems the reasoner already caught

Both were found by running HermiT before the files were handed over, and both are worth knowing because they are exam material.

### `xsd:gYear` is not an OWL 2 datatype

HermiT refused to load the ontology at all:

```
UnsupportedDatatypeException: The datatype 'xsd:gYear' is not part of the
OWL 2 datatype map ... therefore, HermiT cannot handle this datatype.
```

`xsd:gYear` is a perfectly legitimate XSD type, but it is **outside the OWL 2 datatype map**. This is not a warning: the reasoner does not start.

Changed to `xsd:integer`, which is also the better choice on its own merits. Integers compare arithmetically, which CQ4b needs, and negative values express BCE dates without special handling.

### Without disjointness there is nothing to find

An earlier version declared only two groups of disjoint classes. With that version, writing

```turtle
ex:sk90_reject_leprosy po:rejects ex:leprosy .    # leprosy is a Condition, not a Claim
```

produced **no error at all**. The reasoner simply concluded that `ex:leprosy` is *also* a `po:Claim`, and said nothing.

This is the point worth having understood:

> `rdfs:range` forbids nothing. It says: whatever stands on the right is of this type. Put the wrong thing there and OWL does not object, it **retypes it**.
>
> It becomes an error only when the two types **cannot coexist**, and disjointness is what establishes that.

All fifteen top-level classes are now declared pairwise disjoint, and the error is caught.

The same mechanism one level down. `po:hedge` is functional, meaning a claim has one confidence level. But OWL makes **no unique name assumption**, so two different hedges on one claim were not an error either: the reasoner concluded that `po:Probable` and `po:Certain` **are the same individual**. `owl:AllDifferent` blocks on the confidence levels, the discriminating powers and the two frameworks fixed that.

### And one bug in the T-Box itself

`po:declaredIn` was declared with `rdfs:domain po:Claim`. The A-Box also puts `po:declaredIn` on **observations**, which is correct: an observation is published in a source just as a claim is. Result: every observation was inferred to be a `Claim`, and `Observation` and `Claim` are disjoint. Inconsistent.

The domain was removed. The lesson is worth stating plainly: the domain was not describing the world, it was describing what the author imagined while writing. Disjointness is what made the difference visible.

## The test that matters

HermiT currently reports:

```
CONSISTENT
```

That is a boring and expected result, and on its own **it demonstrates nothing**: an empty ontology returns the same verdict.

So run the test that counts. **Break the model on purpose**, confirm the reasoner notices, then put it back. `run_probes.py` does this automatically, but doing two or three by hand in Protégé is worth the ten minutes, because seeing the red popup appear is different from reading that it appeared.

| deliberate error | result |
|---|---|
| reject a `Condition` instead of a `Claim` | **INCONSISTENT** |
| two different hedges on one claim | **INCONSISTENT** |
| two standpoints on one claim | **INCONSISTENT** |
| one observation on two specimens | **INCONSISTENT** |
| a `Claim` where a `Specimen` belongs | **INCONSISTENT** |
| a `Specimen` given a `Condition` directly | **INCONSISTENT** |
| `aboutSpecimen` on a methodological claim | **INCONSISTENT** |
| a claim both negated and affirmed | **INCONSISTENT** |
| `declaredIn` on an observation | consistent, allowed |
| two framed contents on one claim | consistent, allowed by design |
| `appliedTo` on a methodological claim | consistent, the sanctioned form |

The sixth is the important one. Writing `po:proposesCondition` directly on `ex:sk90` **makes the ontology inconsistent**. NCQ1 is no longer only a query that returns nothing: it is something the model physically prevents you from writing.

That table belongs in the README, and at the oral it is the answer to "how do you know your constraints work?".

---

## Why this step is worth points

Most projects load the reasoner, read "consistent" and move on. This one can say three things that almost nobody says:

1. the reasoner found a real problem before submission (`xsd:gYear`, and the `declaredIn` domain);
2. the constraints were **verified** by introducing deliberate errors, not merely declared;
3. the limits that remain are documented, with the alternatives considered and the reason they were rejected.

> An explained inconsistency is worth more than a consistency obtained by accident.
